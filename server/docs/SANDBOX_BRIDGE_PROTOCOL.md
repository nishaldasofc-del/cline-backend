# Termux Sandbox Bridge — `sunset-sandbox-v1` at `/bridge`

The Termux agent (repo `termux-sandbox-bridge`, `npm run bridge:agent`) connects **out** to this server. The server
then sends one request frame per operation; the agent answers with one response frame carrying the same `id`.
This is separate from the per-user `cline-bridge.v1` socket at `/v1/bridge` (see `BRIDGE_PROTOCOL.md`); the two coexist.

```
Termux agent ──(outbound WSS)──► wss://<host>/bridge ──► SandboxHub ──► POST /v1/admin/bridge/execute ──► caller
```

## Configuration
| Env var | Where | Notes |
|---|---|---|
| `BRIDGE_TOKEN` | Render **and** Termux | >= 24 printable chars, no spaces. **Must differ from `SERVER_AUTH_TOKEN`** (boot fails otherwise). Unset: `/bridge` answers `503 bridge_disabled`. |
| `BRIDGE_MAX_DEVICES` | Render | default 16 |
| `BRIDGE_AGENT_MAX_PAYLOAD_BYTES` | Render | default 8 MiB (frames above this close that device's socket with 1009) |
| `BRIDGE_OP_TIMEOUT_MS`, `COMMANDS_MODE`, `COMMAND_ALLOWLIST`, `COMMAND_TIMEOUT_MS` | Render | existing settings, reused |
| `RENDER_WSS_URL` / `RENDER_URL`, `BRIDGE_TOKEN`, `DEVICE_ID`, `SANDBOX_DIR` | Termux | agent side |

Generate a token: `openssl rand -base64 32 | tr -d '=+/\n'`.

## Handshake (HTTP upgrade)
`GET /bridge` with the token in `Authorization: Bearer`, `x-bridge-token`, or `?token=` (first one present is used) and the device in
`x-device-id` or `?device_id=` (`[A-Za-z0-9._:-]{1,64}`). No WebSocket subprotocol is negotiated.

| Answer | Meaning (`X-Cline-Error` header) |
|---|---|
| `101` | registered |
| `401` | missing/wrong token (`bridge_unauthorized`) |
| `400` | missing/invalid device id (`bridge_bad_device_id`) |
| `503` | `BRIDGE_TOKEN` not configured (`bridge_disabled`), device limit reached (`bridge_capacity`), or shutting down |

Rejections happen **before** the WebSocket exists. The token is never logged.

## Registration
Immediately after the upgrade the server sends, and the agent stores `data.sessionId`:
```json
{"protocol":"sunset-sandbox-v1","id":"reg_ack_<sessionId>","ok":true,"data":{"registered":true,"deviceId":"pixel-7","sessionId":"sess_<ms>_<hex>","hubTimestamp":1700000000000}}
```
One live session per `deviceId`. A new connection with the same id **replaces** the old one (old socket closed `4009`, its in-flight
requests fail with `DEVICE_OFFLINE`). Answers from a replaced session can never satisfy a request on the new one.

## Requests / responses
```json
{"protocol":"sunset-sandbox-v1","id":"req_<uuid>","type":"read_file","path":"src/a.ts","deviceId":"pixel-7"}
{"protocol":"sunset-sandbox-v1","id":"req_<uuid>","ok":true,"data":"…","deviceId":"pixel-7","sessionId":"sess_…"}
{"protocol":"sunset-sandbox-v1","id":"req_<uuid>","ok":false,"error":{"code":"FILE_NOT_FOUND","message":"…"}}
```
The wire `id` is always generated by the server. Results are schema-validated; a malformed one becomes `BAD_RESPONSE`.

| `type` | fields | `data` |
|---|---|---|
| `ping` | — | `{status:"pong",timestamp,workspace}` |
| `list_files` | `path?`, `recursive?` | `[{name,path,isDirectory,size,mtimeMs}]` |
| `read_file` | `path`, `encoding?` (`utf-8`\|`base64`) | string |
| `write_file` | `path`, `content`, `encoding?`, `createDirs?` | `{path,bytesWritten}` |
| `delete_file` | `path`, `recursive?` | `{path,deleted:true}` |
| `mkdir` | `path`, `recursive?` | `{path,created:true}` |
| `run_command` | `command`, `args?`, `timeoutMs?` (<= 120000) | `{exitCode,stdout,stderr,stdoutTruncated?,stderrTruncated?}` |

(`auth` is a Sunset-frontend operation and is never forwarded to a device.)

### What the server refuses before anything reaches the phone
- Paths that are empty, > 1024 chars, contain NUL or `\`, start with `/` or `~`, or contain a `..` segment. Paths are relative to the agent's sandbox root.
- `run_command`: `COMMANDS_MODE` (`off` / `allowlist` / `passthrough`) and `COMMAND_ALLOWLIST` apply. `command` must be a bare program name;
  shell operators (`; & | < > \` $()`) are rejected; absolute/`..` arguments are rejected. The agent runs a command **in a shell** when it
  receives no `args`, so the server only ever forwards a validated bare name (+ argv) — a shell line cannot be smuggled through.
- Frames larger than the payload limit, unknown operations, wrongly typed fields.

## Routing
Explicit `deviceId` → exactly that device (`DEVICE_NOT_FOUND` if absent). No `deviceId` → the single connected device;
`DEVICE_OFFLINE` if none; `DEVICE_AMBIGUOUS` if several (the server never guesses). Max 8 operations in flight per device (`DEVICE_BUSY`).

## Failure handling
| Situation | Result |
|---|---|
| Device does not answer in time | `BRIDGE_TIMEOUT` (late answer ignored). `run_command` allows `timeoutMs` + 5 s |
| Socket drops / replaced / server shutdown | in-flight requests fail `DEVICE_OFFLINE`; device removed from the registry |
| No pong for one 20 s heartbeat interval | socket terminated, same as a drop |
| Agent sends non-JSON, wrong protocol, no `id` | close `1008`; binary frame → `1003`; oversize → `1009` |
| Device reports an error | passed through unchanged (`FILE_NOT_FOUND`, `PATH_OUTSIDE_SANDBOX`, `COMMAND_TIMEOUT`, …) |
| Render restarts | sockets close (`1001`/abnormal); the agent's built-in backoff reconnects and re-registers with a new `sessionId` |

## Admin REST (all require `Authorization: Bearer <SERVER_AUTH_TOKEN>`; `BRIDGE_TOKEN` and user tokens get `401`)
- `GET /v1/admin/bridge/devices` → `{enabled, devices:[{deviceId,sessionId,connectedAt,lastSeenAt,remoteAddress,pending}]}`
- `POST /v1/admin/bridge/execute` — body: an operation plus optional `deviceId` and `id` (echoed back). Returns the response envelope.
  `ok` is authoritative. HTTP status reflects only failures to *route*: `400` invalid, `403` command refused, `404` unknown device,
  `409` offline/ambiguous, `413` too large, `429` busy, `502` bad device result, `504` timeout. Errors reported by the device stay `200` with `ok:false`.
  Any configured secret appearing in a device's output is replaced with `[redacted]`.

## Security notes
- The agent's sandbox jail (realpath/symlink confinement) is the real file boundary; the server cannot enforce it. Keep the agent's `SANDBOX_DIR` dedicated.
- The current agent also puts the token in the URL query (`?token=`). Render's request logs may record URLs, so treat `BRIDGE_TOKEN` as exposed
  to your Render logs and rotate it if they are shared. Removing the query param from `buildTargetUrl()` in the agent is safe: it already sends the headers.
- Rotate by changing `BRIDGE_TOKEN` in Render and Termux; connected devices stay connected until their next reconnect.
- Not wired in: the Cline agent loop does not call this hub; it keeps using the per-user `/v1/bridge` workspace. This hub is the device
  registry + router that Sunset (or any trusted backend) drives over the admin REST API above.
